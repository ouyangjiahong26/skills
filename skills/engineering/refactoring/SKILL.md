# 重构

在行为完全不变的前提下改善代码内部结构。对应先失败、再通过、后重构循环里的重构段：只在测试通过的基线上动作，从通过到通过。要消除的异味通常来自 code-review 报告或用户指认。

## 前置条件：安全网先行

1. 确认测试或验证回路当前全部通过，且覆盖到要动的区域（搭回路的手法见 diagnosing-bugs 的阶段 1）。
2. 覆盖不到的区域先补测试，再动结构。
3. 补不出测试时分两种情况：
   - 架构在挡（依赖不可注入、测试面太浅）：能用重构手法解开的死结，先解开再补测试。
   - 死结解不开：停下来，向用户报告缺口与原因。没有安全网的结构大改不是重构，不裸拆。

## 小步循环

一次只做一个重构动作（一次改名、一次搬移、一次抽取），做完立刻跑全部相关测试：

- 通过了：记录这一步（手法、文件、验证命令、结果），它可独立验证、可独立提交。然后开始下一个动作。
- 失败了：立刻回滚这一步，重做或换手法，绝不在失败的基础上叠改。
- 中途不新增功能、不改行为：发现该改的记下来，留给重构完成后的独立改动。功能与重构混在一起，测试失败了就分不清是谁的错。

## 手法目录：异味到手法

异味的定义与清单以 code-review 的异味基线为准，此处只列映射：

| 异味 | 手法 |
|---|---|
| 神秘命名 | 改名。想不出诚实的名字，先治设计再改名 |
| 重复代码 | 抽公共，两边都调它 |
| 依恋情结 | 搬移函数，搬到它羡慕的那份数据上 |
| 数据泥团 | 拢成一个类型，传它 |
| 基本类型偏执 | 给概念建小类型 |
| 重复 switch | 以多态替换，或两边共享一张映射表 |
| 霰弹手术 | 把一起变的东西截拢到一个模块 |
| 发散式变化 | 拆模块，让每个模块只为一种原因变 |
| 投机式泛化 | 内联删除，等真实需要出现再加 |
| 消息链 | 在链首藏一个中间方法，收拢这段导航 |
| 中间人 | 内联转发，调用方直接调真正的目标 |
| 被拒的遗赠 | 以组合替换继承 |

## 何时重构，何时重写

有测试锚点且结构可渐进改善：走本 skill 的小步循环。

同时满足三条才考虑重写，且先向用户提出：模块没有可用测试、公共接口面小（调用方少而集中）、行为大多已死（任务要求不再要它）。重写前先把现存行为原样断言成测试、锁住它，重写期间新旧实现对着同一套测试跑差分。

## 公共接口变更不算重构

改对外可见的东西（签名、参数、返回值、错误语义、事件）是行为变更，不是重构：退出本循环，按编码准则的“完整迁移”走（更新所有调用方、测试和文档，不保留无需求的兼容层）。

## 完成条件

- 测试全程通过：每步动作前后都验证过，无一步在失败状态收尾。
- diff 无公共接口变更：对外签名、错误语义、输出格式逐项比对不变。
- 每步有验证记录：手法、文件、跑过的命令与结果，逐条可对上独立提交。
